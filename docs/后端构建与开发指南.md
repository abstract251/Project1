# 缘遇后端 · 构建与开发指南

> 适用目录：`backend/`　|　目标环境：Linux / WSL2（代码依赖 epoll / inotify / sys/socket.h）
> 构建系统：CMake ≥ 3.16（`backend/` 下共 4 个 CMakeLists.txt，分层管理）

---

## 1. 目录结构

```
backend/
├── CMakeLists.txt            # 顶层：项目名 / C++17 / 输出目录 / 编译选项 / 全局头文件路径
├── include/                  # ★ 所有头文件（全局可见：顶层 include_directories(include) 已配好）
│   ├── error.h               #   错误处理声明
│   └── socket.h              #   Socket 类声明
├── src/                      # ★ 所有源文件（每个模块一个子目录）
│   ├── CMakeLists.txt        #   子目录入口：登记 common / server / client 模块
│   ├── common/               #   ★ 公共代码库（多个程序共用，编译为静态库 common）
│   │   ├── CMakeLists.txt    #   add_library(common STATIC ...) + PUBLIC 头文件路径
│   │   ├── error.cpp         #   错误处理实现
│   │   └── socket.cpp        #   Socket 类实现
│   ├── server/
│   │   ├── CMakeLists.txt    #   server 可执行目标（本程序源文件 + 链接 common）
│   │   └── server.cpp        #   服务端主程序（TCP socket 基础）
│   └── client/
│       ├── CMakeLists.txt    #   client 可执行目标（本程序源文件 + 链接 common）
│       └── client.cpp        #   联调测试客户端
├── bin/                      # ★ 编译产物（可执行文件），已被 .gitignore 忽略
└── build/                    # ★ CMake 构建目录（Makefile 等），已被 .gitignore 忽略
```

**头文件组织约定（当前已统一）**：公共头文件直接放 `include/` 根目录，
源码中一律写 `#include "error.h"` / `#include "socket.h"`；模块专属头文件放
`include/<模块名>/`，写 `#include "<模块名>/<文件名>.h"`。CMake 只配一次
`include_directories(include)`，全项目生效。

## 2. 构建命令清单（在 `backend/` 目录下执行）

| 命令 | 作用 | 说明 |
| --- | --- | --- |
| `cmake -S . -B build` | **配置**：检测编译器、生成 Makefile | 只需在首次或改了 CMakeLists.txt 后执行；输出 "Build files have been written to" 即成功 |
| `cd build && cmake ..` | 同上（等价写法） | 你已经用过的写法，效果完全一样 |
| `cmake --build build -j` | **编译**：把源码编译链接成可执行文件 | 产物输出到 `bin/`；**配置 ≠ 编译，这一步不能省** |
| `cd build && make -j` | 同上（等价写法） | `-j` 并行编译，可加数字如 `-j4` |
| `cmake --build build --target server` | 只编译 server 目标 | `--target client` 同理；改代码后增量编译通常很快 |
| `cmake --build build --target clean` | **清理**：删除编译产生的 .o 和可执行文件 | 等价 `cd build && make clean`；**不需要在 CMakeLists 里写清除命令**，CMake 生成的 Makefile 自带 clean 目标 |
| `cmake --build build --target clean && cmake --build build -j` | 清理后重新完整编译 | 排查疑难编译问题时常用 |
| `rm -rf build && cmake -S . -B build` | **彻底重置**：删掉整个构建目录重新配置 | 改了目录结构 / 换编译器 / 缓存异常时用 |
| `./bin/server` | 启动服务端 | 监听 `127.0.0.1:3011`，阻塞等待客户端连接 |
| `./bin/client` | 启动客户端（另开终端） | 连上后 server 打印客户端 IP/端口，即联调成功 |
| `ls -l bin/` | 查看产物 | 应有 `server` 和 `client` 两个可执行文件 |

### 2.1 常见错误对照

| 报错 | 原因 | 解决 |
| --- | --- | --- |
| `Error: .../build/build is not a directory` | 在 `build/` 目录**里面**又写了 `cmake --build build` | 在 `backend/` 根目录执行；若已在 build 内，直接 `make` |
| `bin/` 是空的 | 只执行了配置（`cmake ..`），没执行编译 | 补执行 `make -j` 或 `cmake --build build -j` |
| `fatal error: xxx.h: No such file or directory` | 头文件不在 include/ 下，或写错了路径 | 头文件放 `include/` 根目录（或 `include/<模块名>/`），源码里按对应路径 `#include`；include 路径顶层已全局配好，不用改 CMake |
| 编译警告 `-Wwrite-strings` | `errif` 形参用了 `char *` 接收字符串字面量 | 已修复为 `const char *`（见 error.h / error.cpp） |
| `undefined reference to 'errif(bool, char const*)'` | 某目标调用了 `errif()`，但该目标没有链接包含实现的库（只有声明没有实现） | 在该目标 CMakeLists 里加 `target_link_libraries(该目标 PRIVATE common)`（errif 实现在公共库 common 里，server / client 都已链接） |
| `Cannot find source file: ...error.cpp` | 源文件被移动/删除，但 CMakeLists 里的文件名还在 | 同步更新对应 CMakeLists 的文件列表；移动过文件后建议 `rm -rf build` 重新配置 |

## 3. 以后加代码怎么改（重点）

### 3.1 新增一个头文件

- 公共头文件放：`backend/include/` 根目录（如 error.h、socket.h）
- 模块专属头文件放：`backend/include/<模块名>/<文件名>.h`
- 写什么：必须有**头文件保护**（`#ifndef` / `#define` / `#endif`，参考 error.h）
- 怎么用：源码里按路径 `#include "error.h"` 或 `#include "<模块名>/<文件名>.h"`
- 改 CMake 吗：**不用改**——顶层 `include_directories(include)` 已全局生效

### 3.2 给现有目标（server / client）新增源文件

例：给 server 加一个 `http_parser.cpp`：

1. 把文件放到 `backend/src/server/http_parser.cpp`
2. 编辑 `backend/src/server/CMakeLists.txt`，在 `add_executable(server ...)` 的括号里**追加文件名**：

```cmake
add_executable(server
    server.cpp
    http_parser.cpp        # ← 新加的一行
)
```

3. 重新配置 + 编译：`cmake -S . -B build && cmake --build build -j`
   （CMakeLists 变了必须重新配置，否则新文件不会被编译）

> ⚠️ 只有**本程序专属**的源文件才加到这里；多个程序要共用的代码请走 3.3 的公共库。

### 3.3 新增公共代码（多个程序共用）→ 放进 common 库

例：加一个 `logger` 模块：

1. 把 `logger.cpp` 放到 `backend/src/common/` 下
2. 编辑 `backend/src/common/CMakeLists.txt`，在 `add_library(common STATIC ...)` 里**追加文件名**：

```cmake
add_library(common STATIC
    error.cpp
    socket.cpp
    logger.cpp            # ← 新加的一行
)
```

3. 使用方（server / client）**不用改**——它们已经 `target_link_libraries(... PRIVATE common)`
4. 重新配置 + 编译

> 如果公共代码多到要拆成多个库（如单独的 logger 库），那就照抄 common 的模式：
> 建 `src/logger/` 目录 + 写自己的 CMakeLists（add_library(logger STATIC ...) + PUBLIC include 路径），
> 在 `src/CMakeLists.txt` 登记 `add_subdirectory(logger)`，使用方加一行 `target_link_libraries(... PRIVATE logger)`。

### 3.4 各 CMakeLists.txt 各自管什么（改哪个）

| 文件 | 负责内容 | 什么时候要动它 |
| --- | --- | --- |
| `backend/CMakeLists.txt` | 项目名、C++ 标准、输出目录、编译选项、全局 `include_directories(include)` | 几乎不动；加全局选项时改 |
| `backend/src/CMakeLists.txt` | 登记有哪些模块子目录 | 新增模块目录时加一行 `add_subdirectory(...)` |
| `backend/src/common/CMakeLists.txt` | 公共库 common 的源文件清单 | 新增公共源文件时加一行 |
| `backend/src/server/CMakeLists.txt` | server 专属源文件、链接的库 | 给 server 加专属源文件 / 链接新库时 |
| `backend/src/client/CMakeLists.txt` | client 专属源文件、链接的库 | 给 client 加专属源文件时 |

## 4. include 路径是怎么生效的

两条路径，简单地说就是"**全局一把梭 + 公共库兜底**"：

```cmake
# 顶层 backend/CMakeLists.txt —— 全项目生效（对 src/ 及其所有子目录可见）
include_directories(include)   # = backend/include

# src/common/CMakeLists.txt —— 公共库再声明一次（PUBLIC），
# 保证"链接 common 的目标"即使脱离顶层配置也能找到头文件
target_include_directories(common PUBLIC ${CMAKE_SOURCE_DIR}/include)
```

- 编译器遇到 `#include "error.h"` 时，按顺序搜索：① 当前源文件所在目录 → ② `-I` 指定的目录 → ③ 系统目录
- 顶层 `include_directories(include)` 会给所有目标加 `-I backend/include`，所以 `error.h` / `socket.h` 全项目都能找到 ✅
- `common` 库上的 `PUBLIC` 表示：链接它的目标也会自动继承这个头文件路径（双保险，拆库后依然成立）
- 模块专属头文件放 `include/<模块名>/` 后，写 `#include "<模块名>/xxx.h"` 同样能解析

## 5. 当前编译配置一览

| 配置项 | 当前值 | 位置 |
| --- | --- | --- |
| C++ 标准 | C++17（`CMAKE_CXX_STANDARD 17`） | 顶层 CMakeLists |
| 警告选项 | `-Wall -Wextra`（GNU/Clang 自动加） | 顶层 CMakeLists |
| 输出目录 | `backend/bin/` | 顶层 CMakeLists（`CMAKE_RUNTIME_OUTPUT_DIRECTORY`） |
| 默认构建类型 | Debug（可用 `-DCMAKE_BUILD_TYPE=Release` 覆盖） | 顶层 CMakeLists |
| 头文件路径 | `include_directories(include)` 全局生效 + common 库 PUBLIC 双保险 | 顶层 / src/common/CMakeLists.txt |
| 公共库 | `common`（error.cpp + socket.cpp，静态库） | src/common/CMakeLists.txt |

## 6. 平台注意事项

- 本后端只支持 Linux 系（epoll / inotify 为 Linux 专有），Windows 下请在 **WSL2** 中开发
- 在 WSL2 里项目位于 `/mnt/e/...`（drvfs 挂载），读写性能低于 Linux 原生目录；如果编译变慢，可把项目复制到 WSL 家目录（`~/`）编译，或用 `cmake` 的 `-B` 指定其他构建目录
- 每次改动 CMakeLists.txt 后，务必重新执行配置步骤（第 2 节第 1 行命令），否则改动不生效
